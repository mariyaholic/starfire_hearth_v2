# App, UI, persistence and browser audit — 2026-11-14

Scope: application and UI source on the expedition continuation branch, including the exported Web shell. Findings distinguish reproduced behavior from source inspection. Browser tests here use Chromium software WebGL on Linux; they do not certify physical devices or other browsers. The simulation audit is separate.

## States, transitions and boundaries

| Area | States and transitions | Guard or failure boundary |
| --- | --- | --- |
| App routing | Title, campaign, briefing, game, debrief, load, settings, credits and codex are hosted one at a time. Begin creates a session; Continue loads a verified envelope and opens game or debrief according to outcome. | Route changes close overlays and detach the old screen. Flow navigation now ignores detached screens; save-load and delete callbacks also check attachment before acting. Canonical campaign wins are recorded at debrief. Progress writes use a checked pending file and rename; a failed write keeps the in-memory change and shows a deferred warning. |
| Session and orders | New/load/continuation creates a fresh queue and increments `session_serial`; orders apply to a preview and are committed on turn resolution. | Screens and expedition/event actions capture session identity. Turn resolution now refuses missing state/queue, terminal state, reentrant calls and an outstanding continuation save. Checklist confirmation captures the authoritative state identity so a late callback cannot resolve the following turn. |
| Expedition continuation | An eligible won preview creates an independent continued state and snapshots live presentation. Native saves before resuming; Web waits for an exact IndexedDB readback of the envelope. | Pending orders and stale identities are refused; both debrief actions are disabled during the Web wait. On an unconfirmed write, the original live session remains, no compensating write occurs, and the player can retry. A write may finish after timeout. |
| Save/load | Turn resolution writes a rotating auto slot and every fifth turn a checkpoint. Manual save uses the next available numbered slot. Envelopes contain simulation state and live presentation; load checks checksum/schema before resuming. | A `.pending` file is flushed and then renamed to the slot; pending files are not listed. Native rename/write failures return errors and automatic-save errors are surfaced after the transition. Web manual saves wait for exact IndexedDB readback before reporting success. Thumbnail failure does not invalidate a save; checkpoint and auto slots share one frame capture. The load list reads envelope summaries without trusting them for loading. |
| Flow and overlays | AppRoot detaches screens on routing; overlay manager stacks dialogs/drawers, caps toasts and tooltip levels, and clears them on route changes. Layout/theme updates rebuild controls. | Captured callbacks must validate their owning screen/session; this audit fixed a detached load/delete path and an old advisor callback. Rebuilds retain the continuation busy state. |
| Audio and voice | Audio uses separate UI/effects/music players and a voice player. Cue registry tracks metadata and an utterance is not replayed on ordinary refresh. Session changes stop voice; quitting begins coordinated retirement. | Missing voice assets are optional and written event text remains available. Shutdown waits for active audio and renderer retirement, with a bounded timeout warning. |
| World rendering | `Worlds` owns the visual session, appearance store, resource cache and generation scheduler. Session changes bind the saved appearance and restart the visual epoch. Navigation replaces world hosts; WebGL loss suspends generation and the shell offers reload. | Scheduler cancels stale owner/epoch jobs; shutdown drains retired worker tasks. Presentation can contain unknown future fields and is preserved by the save system. |
| Settings and display | Settings load at startup, clamp/validate types and save on change; window/fullscreen changes go through DisplaySettings; layout reacts to window, pointer type, UI and text scales. | Browser view mode also has a localStorage scalar for fast restoration. Settings failures are not surfaced to the player; fullscreen support can be unavailable. |
| Debug probes | Opt-in smoke routes start disposable fixture sessions and some alter settings, save directories or run turns. Probe globals expose test telemetry/actions to the page. | Previously the release Web build also accepted these routes. They now run only in debug exports; release output remains a separate artifact. CI uses a separate debug export for smoke interaction. |

## Confirmed findings and verification

1. **Release smoke route could write an ordinary autosave.** Before the guard, an actual 4.7.2 release Web export opened at `?smoke=begin` started seed 1, resolved a turn and stored `auto_2.json` and its thumbnail in IndexedDB. This could replace the user's corresponding ring slot. Baseline screenshot: [`release-before-smoke.png`](screenshots/release-before-smoke.png). The fixed release was tested in Chromium with an existing sentinel `auto_2.json`; the query produced no smoke execution and the stored bytes remained identical. Fixed screenshot: [`release-after-guard.png`](screenshots/release-after-guard.png). A separate debug export still ran the smoke and produced the expected turn-2 hash. `node tools/web_release_probe.mjs <release-build> <capture-dir>` is the repeatable release check.
2. **Terminal and stale turn requests advanced play.** A direct headless API reproduction advanced a won state from turn 1 to 2. A synchronous turn-resolved listener or preserved checklist callback could also request another turn. The app facade now refuses terminal, pending-save and reentrant resolution; the screen confirms against the original state identity. `--filter game_screen` includes the regression.
3. **Detached load screen could replace the session or delete a save.** A headless integration reproduction called the former screen's preserved load and delete callbacks after routing to title; it navigated into the old game and removed the slot. The callbacks and common flow navigation now reject detached screens. `--filter flow_screens` covers both.
4. **An old advisor callback could modify a new session.** A headless reproduction started a same-seed session and invoked the old screen's tutorial acknowledgment: the new queue grew from zero to one. The callback now checks attachment and session serial. `--filter old_advisor_callback` covers it.

5. **Automatic save failure was silent.** A real native click-through using a disposable profile with its save path blocked showed manual save failure, while an End Turn advanced without any automatic-save warning. The handler now posts a deferred warning, limited to the originating session and latest save attempt. Before captures: [manual failure](screenshots/native-before-manual-save-failure.png) and [silent autosave failure](screenshots/native-before-autosave-silent.png). [After capture](screenshots/native-after-autosave-warning.png) shows the warning on the Month 3 report under the same blocked-path setup.
6. **Player command actor was unchecked.** A legal foreign-colony rename was accepted into the player's queue in a headless integration reproduction. `Game.submit` now refuses a command for a different empire; simulation phase handling is reviewed separately.
7. **Checkpoint saves duplicated frame capture.** In a 1920×1080 native Xvfb/llvmpipe fixture, the second thumbnail readback and encoding took 17–33 ms in ten baseline samples (median approximately 26 ms). Auto and checkpoint now use a single encoded capture; a subsequent fixture measured an extra independent readback at 13–38 ms (median approximately 19 ms). The updated actual-render fixture wrote matching nonempty auto/checkpoint PNG bytes; its single checkpoint autosave took 61 ms including both save envelopes and file writes. These measurements include software rendering and PNG work and are not claims about other hardware; the disposable profiling harness reported resources still in use at process exit, so it is not lifecycle-cleanup evidence.
8. **Campaign progress write failure was silent.** A blocked pending-file fixture preserved the previous file while retaining the in-memory win; an integration fixture showed the warning after routing to debrief. Campaign updates now use a checked pending write and rename, with a revision-guarded failure warning.
9. **Parallel CI workers could fail silently.** Bare Bash `wait` without individual PIDs returns success regardless of child failures. CI now records each PID, waits for every child and fails if any failed; `bash tools/test_wait_all.sh` exercises failure and full cleanup.

## Data and privacy

The application reads bundled game data, localized text, icons, art and optional audio, plus user-local settings, campaign progress, game saves, thumbnails and workspace layout. Saves contain player-created game state, scenario/seed/turn and appearance/presentation metadata; thumbnails contain the visible game frame. They are stored under Godot `user://` on native platforms and the origin-scoped `/userfs` IndexedDB on Web. Settings use `user://settings.cfg`; the Web view-mode preference additionally uses an origin-scoped localStorage key. Campaign progress is local `user://campaign.json`.

An isolated 4.7.2 Web fixture invoked the production verifier three times concurrently: two exact matches succeeded, a missing-path check timed out, and the operation map returned to zero. The [result](fixtures/web-verifier-result.json) and [fixture source](fixtures/web-verifier-fixture.gd.txt) are retained; this is a scripted browser fixture, not a manual gameplay test.

The Web verifier accesses only the same-origin IndexedDB `/userfs` `FILE_DATA` store, with the target path and expected envelope passed via JSON encoding; it does not transmit the content. Display/fullscreen, pointer detection and WebGL recovery use browser APIs. Debug-only probe globals are visible to other scripts on the same page and contain test state/telemetry. Source searches of app/UI/simulation found no application HTTP client, WebSocket, analytics or upload endpoint. The Web page and packaged assets are downloaded from the hosting origin, and the host/browser may maintain ordinary access logs; this source audit cannot establish a deployment's server policy or exclude behavior added by a host.

## Remaining known limits

- Ordinary Web autosave and campaign-progress writes complete on virtual filesystem completion without the exact IndexedDB acknowledgment used by expedition continuation and manual saves. A page close immediately afterward can precede browser persistence; this is a source-supported durability gap, not a newly claimed reproduction of those separate flows.
- Settings write errors are not surfaced. Preserving unknown ConfigFile keys and the independent Web localStorage scalar requires care if changing this path; no settings persistence redesign was made in this audit. Save deletion now asks for confirmation and verifies that the selected slot has not changed before deleting. The native 200% phone-layout playtest captured the [confirmation](screenshots/native-delete-confirmation-phone200.png); Cancel preserved the target, and Confirm removed only that target. The [remaining row](screenshots/native-delete-target-removed-phone200.png) is a separate fixture save, confirmed by file and UI identifiers.
- Load synchronously parses all listed envelopes and decodes available thumbnails; manual slot count is unbounded. This is a source-supported performance candidate, not a claim of demonstrated player-visible latency in this run.
- No browser durability guarantee is claimed if storage is disabled, blocked, full or cleared by the browser. Native and browser test results do not cover every platform, hardware renderer or storage implementation.
