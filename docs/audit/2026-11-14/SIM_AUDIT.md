# Simulation state-machine audit — 2026-11-14

Scope: the pure simulation and its command, save, content, bot telemetry and outsourced-asset intake boundaries, starting from `bb6e993` on `feat/expedition-continuation`. This is a source audit with focused reproductions, not a proof of all states or an end-to-end visual playtest. The application, browser persistence, release workflows and screenshots are covered by the parallel application audit. No schema version, scenario content, phase ordering or golden hashes were changed here.

## Reproduced faults and fixes

1. **Queued-command alias:** submitting a rename, mutating the original or the object returned by `commands()`, then ending the turn executed a different rename from the preview. The new queue snapshots both boundaries. `test_submitted_and_exported_command_mutation_cannot_change_queued_order` failed twice before the fix and passes after it.
2. **Foreign actor:** a player-supplied otherwise legal command naming a different empire changed that empire's colony; the same order remains legal when explicitly supplied on the AI path. The queue and processor now reject the player-sourced attempt without changing the preview. The app facade independently guards its input.
3. **Terminal state:** a direct `TurnProcessor.run` call on known won/lost states applied an order, changed resources and incremented the turn. Known scenarios now absorb those calls. Both existing golden sets remain byte-for-byte unchanged because the intentionally uncatalogued TinyState fixture keeps its historical behavior.
4. **Unresolvable checked save:** valid-checksum saves with a missing pending event chain or step loaded despite having no possible choices; valid-checksum ships with nonexistent task targets or unknown task types also loaded and became permanently blocked or discarded work. Content/target/positive-time checks now fail closed. Genuine pending events and active surveys still load.
5. **Unnormalized saved growth:** a checksummed save containing growth `1000000` loaded and generated at least 100 populations in a single turn. A larger value would iterate proportionally. Stable save/turn boundaries now reject it.
6. **Fixed-point overflow and negative resource costs:** a too-large authoring amount wrapped across signed 64-bit range, including into a negative cost; arbitrarily long inputs emitted a conversion error. Decimal comparison rejects overflow before conversion. Resource maps with negative amounts now fail data validation; signed event effects remain supported.
7. **Outsourced batch traversal and false check mode:** a real test ZIP with batch `../../../../escaped` wrote a PNG outside the report directory from a `--check` invocation. Metadata is validated before any handler/write, check mode writes nothing, and invalid batches produce a nonzero CLI status. ZIP input size ceilings guard the named pre-decode reads.
8. **Entity key/id mismatch:** checksummed saves could hold a planet, colony, ship or lane whose internal id differed from its dictionary key, breaking later lookups. Invariants now require the ids to agree for all id-keyed entity maps.
9. **Stale allocation counter:** a checked save with the colony counter below an existing id loaded and a valid colonisation overwrote the capital. Allocation now skips live ids for entity maps, build queues, pending/scheduled events and scheduled effects; an exhausted signed 64-bit counter restarts its search before overflow. Existing stale/omitted counters need no schema migration.
10. **Telemetry false-green coverage:** missing policy/difficulty groups and un-replayed runs could be SKIP while advisory CI returned success; files were silently ignored if malformed. Explicit matrix expectations and replay checks are fatal independently of advisory balance, with a real subprocess test for a missing file/group.

## Evidence and limitations

- `godot --headless --path . -s tests/run_tests.gd -- --filter sim_audit_authority` covers the simulation reproductions, including valid pending and in-progress task saves.
- `godot --headless --path . -s tests/run_tests.gd -- --filter telemetry_coverage` checks missing matrix entries, wrong scenario, duplicate seeds, replay coverage and the CLI exit status.
- `python3 -m unittest discover -s tests/tools -p test_import_assets_security.py` covers traversal, malformed batches, no-write check mode and size limits; the original traversal was additionally exercised with an actual vignette ZIP in a temporary directory.
- Focused final checks with Godot 4.7.2: authority 16 tests / 76 checks; telemetry coverage 3 / 13; command 8 / 118; saves 5 / 24; Shroud 10 / 114; golden hashes 4 / 6. Earlier focused FX 5 / 29, data 6 / 23, events 8 / 71, travel 12 / 95, auto-explore 12 / 69, continuation 14 / 130, construction 10 / 60 and `tools/validate_data.gd` also passed. Seven Python asset security tests passed. The lead owns the consolidated suite, CI/release checks and application/visual testing.
- Checksums and catalog references are not signatures. The code has no general untrusted-file memory quota or comprehensive malicious-save fuzzer; resource bounds outside the proven growth loop and authored decimal conversion remain an audit limitation. Synthetic test states can intentionally violate normal player/session assumptions.
